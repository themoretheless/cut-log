# CutLog

CutLog — локальный браузерный набор инструментов для раскроя листовых
материалов:

- **Оптимизатор раскроя** размещает прямоугольные детали на листах с учетом
  ширины реза, разрешенного поворота и нескольких гильотинных эвристик.
- **Конструктор коробки** создает параметрическую коробку шип-паз, показывает
  сборку и детали в 3D и экспортирует SVG для лазера.
- **Доска SKÅDIS** создает параметрическую перфопанель, совместимую с сеткой
  аксессуаров IKEA SKÅDIS, и экспортирует ее в SVG или DXF.

Интерфейс работает на русском и английском. Геометрия, оптимизация и проекты
остаются в браузере; данные никуда не загружаются.

## Возможности

### Оптимизатор раскроя

- Rust/WASM-оптимизатор с учетом реза и поворота детали.
- Девять стратегий и режим **Auto**, выбирающий сначала минимум листов, затем
  лучшую эффективность.
- Вычисление идет в отменяемом module Worker и не блокирует интерфейс.
- Ограничения безопасности: максимум 1 000 копий одной детали и 2 000 деталей
  после раскрытия количества; проверка выполняется до WASM и повторно в Rust.
- Пресеты листов, импорт, фильтры, сортировка, массовые операции, перенос мышью
  и клавиатурой, undo/redo, снимки, ссылки, расчет цены и экспорт.
- Доступные с клавиатуры SVG-карты листов.

### Конструктор коробки

- Геометрия шип-паз из ширины, высоты, глубины, толщины, реза, размера шипа,
  числа полок и скоса.
- Единая модель ограничений не допускает геометрически невозможные параметры.
- Three.js-сборка и галерея деталей с полным освобождением GPU-ресурсов.
- SVG-экспорт отдельных деталей и полного раскроя.

### Доска SKÅDIS

- Параметрическая сетка пазов из размера доски, размера паза, шага, отступа от
  края и сдвига рядов и столбцов, с проверкой на совместимость со стандартной
  сеткой SKÅDIS.
- Предпросмотр в стиле чертежа: отступы и шаг измеряются по осевым линиям
  пазов, вид можно приближать и двигать, а разметка сохраняет постоянный размер
  на экране.
- Режим сетки 3 × 3 показывает габарит сборки и расстояние между отверстиями
  соседних досок, подсвечивая размер, который разрывает шаг сетки.
- Подгонка размера доски до ближайшего меньшего, при котором шаг отверстий
  одинаков и внутри доски, и через стык.
- Экспорт в SVG и DXF в миллиметрах для лазера и ЧПУ.

## Как разбираться по маленьким частям

1. `frontend/src/services/types.ts` — словарь данных.
2. `lib/optimizerLimits.ts` и `validatePiece.ts` вместе с тестами — граница
   доверия и ограничения.
3. `services/optimizer.ts` -> `optimizerWorker.ts` ->
   `optimizer.worker.ts` -> `rustService.ts` — один запуск расчета.
4. `crates/core/src/models.rs` и `optimizer.rs` — чистое ядро; WASM и CLI лишь
   адаптеры.
5. `lib/sheetPresentation.ts` и `components/SheetCard.svelte` — представление
   результата; после них проще читать `pages/Home.svelte`.
6. Коробка: `box/constraints.ts` -> `geometry.ts` -> `useBoxModel.svelte.ts` ->
   `box/three/*` -> `pages/BoxBuilder.svelte`.

В [ARCHITECTURE.md](ARCHITECTURE.md) есть правила слоев, SOLID/DRY-карта,
диаграммы, три выполненные итерации и порядок следующих небольших рефакторингов.

## Архитектура кратко

```text
pages/components -> composables -> services -> Worker/WASM -> Rust core
        |                |              |
        +----------------+------------> pure TypeScript/types
```

Чистые модули не импортируют Svelte и браузерные эффекты. Страницы собирают
компоненты и composables, но не должны повторять в себе правила валидации,
хранения, геометрии и экспорта. Главный оставшийся долг — оркестрация в
`Home.svelte`; она будет выноситься целыми ответственностями, а не механическими
кусочками строк.

## Ревью из 500 пунктов

В [recommendation.md](recommendation.md) находится канонический каталог ровно
из **500 уникальных пунктов** с ID `CL-001`..`CL-500`, типом, приоритетом,
размером и отметкой выполнения. Он охватывает безопасность, корректность
оптимизатора, Worker/WASM, Rust/CLI, архитектуру Home, хранение, импорт,
CAD-экспорт, геометрию коробки, Three.js, доступность, дизайн, мобильную версию,
i18n, тесты, CI, производительность, приватность, продуктовые идеи и
документацию.

Список не копируется целиком в три файла: это нарушило бы DRY и быстро создало
бы три несовпадающих статуса. README дает вход, ARCHITECTURE объясняет границы,
а recommendation содержит все 500 рабочих записей.

## Сборка и запуск

Нужны Rust с таргетом `wasm32-unknown-unknown`, `wasm-pack`, `wasm-opt` и
Node 22+.

```bash
cd crates/wasm
wasm-pack build --target web --release
wasm-opt -Oz --enable-bulk-memory pkg/cutter_wasm_bg.wasm -o pkg/cutter_wasm_bg.wasm

cd ../..
cp -r crates/wasm/pkg/* frontend/wasm/
cp crates/wasm/pkg/cutter_wasm_bg.wasm frontend/public/

cd frontend
npm ci
npm run dev
```

`npm run build` собирает статику в `frontend/dist`.

## CLI

CLI читает JSON из stdin и печатает JSON, либо SVG при `"svg": true`.
Некорректный или слишком большой запрос завершает команду с ошибкой.

```bash
echo '{
  "sheet_width": 2440, "sheet_height": 1220, "kerf": 3, "strategy": "Auto",
  "pieces": [
    { "label": "Полка", "width": 500, "height": 400, "quantity": 3 },
    { "label": "Бок",   "width": 800, "height": 600, "quantity": 2 }
  ]
}' | cargo run -p cutter-cli
```
